# 06 — Faire évoluer le dictionnaire

Le noyau de notation reste stable. Une idée nouvelle peut ajouter un terme ou une formule; elle ne renomme pas rétroactivement une mesure ancienne sans expliquer la conversion.

## Fiche minimale d’une nouvelle entrée

```text
Nom/source du concept :
Phrase de départ :
Domaine(s) :
Objets construits : G / K / X / autre
Relations : type, direction, unité, provenance
Opération topologique : H_k / filtration / application / autre
Signature et unité :
Conditions du test :
Statut : idée / hypothèse / spécification / code / test / observation…
Définition manquante ou ambiguë :
```

## Règles

1. **Lire la source avant de traduire.** Distinguer le texte, le code, les tests et les observations.
2. **Définir l’objet avant l’invariant.** Pas de `H_k` sans graphe/complexe/espace et construction déclarés.
3. **Typer les relations interdomaines.** Une analogie ne devient pas un couplage; un couplage ne devient pas une loi commune sans résultat adapté.
4. **Ne pas fusionner les homonymes.** Une même étiquette source peut cacher des mesures différentes.
5. **Ne pas combler les trous par invention.** Marquer `?`, `OUVERT` ou `À DÉFINIR` lorsque la source n’indique pas le complexe, le seuil, le degré ou la réduction.
6. **Conserver les contre-exemples et versions abandonnées.** Les anciennes formules restent dans l’historique, avec leur statut.
7. **Ne pas tirer une conclusion physique de la notation seule.** La vérité de l’hypothèse dépendra des modèles, contrôles et observations du travail concerné.

## Changement de version

- `0.1` — alphabet initial, grammaire de composition et traductions des formulations explicites repérées.
- `0.x` — ajouts au dictionnaire à partir d’idées/hypothèses nouvelles; pas de refonte silencieuse des entrées existantes.
- `1.0` — seulement après relecture par Jonathan et stabilisation des sens de base.

Les futures formules d’hypothèses se travailleront dans leurs fiches dédiées; ce dépôt garde le vocabulaire commun et son registre d’origine.
